## Transfer Intent

Nautilus is now the method itself. Earlier, the Nautilus parent journey held a broader family shape: method, protocol, Mirror extension and desktop harness. That shape served exploration, but the product topology has changed.

The Tauri application body now continues as Mirror Desktop in `mirror-mind-ai/mirror-desktop`. The method body becomes the canonical Nautilus repository in `mirror-mind-ai/nautilus`.

## What Was Preserved

The repository previously living at `vida-criativa/nautilus/agentic-method` was copied with its Git history into the new canonical path. The visual mark `assets/nautilus-method.png` was committed before transfer so the method source includes the current public-facing asset.

Runtime projection cache under `.mirror/` was intentionally not copied into the new repository. It is local generated state, not method source.

## New Canonical Meaning

`nautilus` no longer names a four-body family by default. It names the method: the conceptual and pedagogical grammar for agentic growth, realization and coherent expansion.

Protocol, extension and desktop concerns may still exist, but they should not make the Nautilus method repository carry application or runtime responsibilities by default. Mirror Desktop owns the desktop body. Mirror extensions own operational integration. The method repository owns language, principles, concepts, cases and teachable practice.

## Continuity Rules

Historical conversations, tasks and exploratory records from `nautilus-agentic-method` remain historical provenance. Future work should happen on the `nautilus` journey unless it explicitly concerns old records or migration evidence.

The repository transfer does not require `git filter-repo`, because the project remains at repository root and keeps its original commit history.
