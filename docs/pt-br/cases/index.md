# Casos canônicos

Casos canônicos existem para pressionar a gramática Nautilus contra situações reais.

Eles não são exemplos decorativos. Eles ajudam a perceber se a linguagem simplifica o trabalho, revela lacunas e preserva correspondência entre Method, Protocol, Mirror Extension e Harness.

## Casos iniciais

| Caso | Tipo | Função |
| --- | --- | --- |
| [Retry do assessment](retry-assessment.md) | Retrospectivo | Reconstruir uma [realização](../method/realization.md) já ocorrida para testar se a gramática reconhece intenção, [entrega](../method/delivery.md) e [evidência](../method/evidence.md) |
| [Logística dos livros](book-logistics.md) | Prospectivo | Formular uma [Missão](../method/mission.md) viva antes de executar, testando o Teste de Inteireza |

## Como ler os casos

Cada caso deve registrar:

- [Jornada](../method/journey.md) envolvida;
- [Participantes](../method/participant.md) conhecidos;
- Missão formulada;
- Entrega esperada ou observada;
- Evidência disponível ou necessária;
- Realização reconhecida ou desejada;
- [Integração](../method/integration.md) possível;
- lacunas reveladas pela gramática.

Nesta fase, os casos podem conter campos ainda não formalizados. Quando isso acontecer, o caso deve marcar a lacuna em vez de fingir que a versão atual já a resolve.
