# Mission Integrity Test

The [Mission](mission.md) Integrity Test verifies whether a Mission is sufficiently formulated before advancing.

## Aristotelian foundation

The test implicitly rests on the Aristotelian reading of the four causes. See [Aristotelian influences](aristotelian-influences.md).

A minimally whole Mission needs enough context and materiality in the [Agentic Map](agentic-map.md), recognizable form, authorized movement, and situated finality. This prevents the Mission from being only a vague intention, a rushed task, or hidden execution.

## Test questions

A minimally whole Mission answers four questions:

| Cause | Nautilus question | Function |
| --- | --- | --- |
| Material | Is there enough context and materiality in the [Agentic Map](agentic-map.md) to know what the Mission is made of? | Prevent the Mission from becoming too abstract |
| Formal | What directed intention is being named? | Give recognizable form to the movement |
| Efficient | What movement is authorized now, and does the Mission remain without hidden execution? | Separate formulation from premature execution |
| Final | Why does this intention matter now? | Situate the Mission's finality |

Beyond these four questions, the experimental version applies a common recognition check: can Method, Protocol, Mirror Extension, and Harness recognize the same minimal fields?

## Passing criterion

The Mission passes the test when the four causes are sufficiently answered, the common recognition check passes, and everything remains proportional to the formulation chamber.

Passing the test does not mean the Mission was executed. It means it gained enough form to be recognized.

## Failure criterion

The Mission fails when there is not enough context and materiality in the [Agentic Map](agentic-map.md), the intention is vague, the purpose is absent, execution appears prematurely, or the minimal form is not recognizable by the Nautilus Family components.

Failure is not moral error or disposal. It is information about form. The Mission can be adjusted until it becomes whole.

## Minimal example

```yaml
mission:
  id: mission-001
  title: Formulate the first Nautilus mission
  purpose: Prove that Nautilus can name a directed intention before execution.
  status: formulated
```

Reading through the test:

| Cause or check | Answer |
| --- | --- |
| Material | The minimal context is the first Mission formulation chamber in the Nautilus method, with a simple YAML artifact as initial materiality |
| Formal | Formulate the first Nautilus Mission |
| Efficient | Only formulation is authorized; status is `formulated` |
| Final | Prove that Nautilus can name intention before execution |
| Common recognition | Yes, the minimal fields are recognizable |

## Human use

The test should be used as conversation, not bureaucracy.

It helps the [Participant](participant.md) perceive whether there is enough form to continue or whether there is still fog in the intention.

## Agentic use

An agent can use the test as a phase guard.

If the user asks for execution when the Mission is not yet whole, the agent should help formulate before acting. If the user adds too many details, the agent can separate formulation from execution.

## Boundary

The Integrity Test does not approve a plan, authorize execution, validate [Delivery](delivery.md), or recognize [Realization](realization.md). It belongs to the formulation chamber.
