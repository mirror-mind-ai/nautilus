# Integration

Integration is the mechanism of the **Integrated Expansion** principle.

**Each Realization should expand the Journey's capacity without breaking the form that allows it to continue.**

Integration is the gesture that preserves learning, decision, criteria, Impact signals, or capacity in the next turn of the Journey.

It prevents a [Realization](realization.md) from becoming an isolated episode. When Integration happens, realized work changes the starting point of the next session: the Journey continues with more language, more memory, more criteria, and more power to realize.

## Why the concept exists

Without Integration, a Journey can produce Deliveries, recognize progress, and still restart almost from zero in the next encounter.

Learning remains dispersed among conversations, files, impressions, and memories. The Realization happened, but it did not sufficiently increase the future capacity of the Journey.

Integration exists to transform Realization and what was learned from Impact into future capacity for Value Generation.

## What can be integrated

Integration may preserve:

- a decision made;
- learning about the work;
- more precise language;
- a quality criterion;
- important Evidence;
- useful Impact signals;
- a change in practice;
- a way of operating;
- a new capacity;
- a question that must remain alive;
- a more mature next Mission.

## Relation to reliable continuity

[Reliable continuity](reliable-continuity.md) is the effect of well-done Integrations.

When Integration is weak, the next session needs to reconstruct context. When it is strong, the Journey knows where it stopped, what was realized, what was learned, and how this changes the next movement.

## Relation to realization intelligence

[Realization intelligence](realization-intelligence.md) grows when Integration turns each spiral movement into accumulated capacity.

The Journey does not learn merely because something happened. It learns when what happened is preserved in a useful form for realizing better later.

## Integration without bureaucracy

Integration does not need to be heavy.

Sometimes a recorded decision is enough. Sometimes a short synthesis. Sometimes a criterion update, a link, a memory, a checklist, a change in the next plan, or a preserved question.

The size of Integration should be proportional to the value of the learning and to the future value it helps generate.

## Practical criterion

An Integration is good when Participants can answer:

- what value was generated;
- what was learned;
- which decision, criterion, or capacity needs to be preserved;
- where this will be available for the next session;
- how this changes the next movement;
- whether the Integration is proportional, without becoming bureaucracy.

## Boundary of the current version

In version `0.1.0-experimental`, Integration is a founding concept of the method language. Its formats, states, and operational mechanisms will be stabilized in future chambers.
